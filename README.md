# scheduler_bot

Telegram-бот на **Python + aiogram 3**, который расставляет посты в канале с заданным интервалом.

Вы присылаете боту пост — он ставит его в очередь канала на **N часов позже самого последнего
поста в очереди**. Уже запланированные посты не трогаются. При смене интервала вся очередь
пересчитывается начиная с первого поста:

| Пост | Интервал 1 ч | Интервал 2 ч |
|------|--------------|--------------|
| 1    | 13:00        | 13:00        |
| 2    | 14:00        | 15:00        |
| 3    | 15:00        | 17:00        |

## Важно: где хранится «отложка»

Telegram Bot API **не даёт ботам доступа к нативным отложенным сообщениям** канала
(их могут создавать только пользовательские аккаунты). Поэтому бот ведёт свою очередь
в SQLite и сам публикует посты в нужное время (через `copyMessage`, без пометки «переслано»).

Следствия:
- посты, которые вы поставили в отложку вручную через приложение Telegram, бот не видит;
- бот должен работать постоянно (сервер / VPS / Docker);
- не удаляйте посты из чата с ботом до публикации — бот копирует их оттуда.

## Возможности

- выбор канала из тех, где бот — администратор с правом публикации (и вы тоже администратор);
- интервал на каждый канал: `2`, `1.5`, `90м`, `1ч 30м`;
- пересчёт очереди при смене интервала (первый пост остаётся на месте);
- поддержка любого контента: текст, фото, видео, документы, голосовые, опросы, **альбомы**,
  пересланные сообщения;
- `/queue` — список очереди с предпросмотром 👁, удалением 🗑 и кнопкой «Выровнять»
  (убрать «дыры» после удаления);
- уведомление, если пост не удалось опубликовать;
- ограничение доступа списком `ALLOWED_USERS`.

Если очередь пуста, новый пост встаёт через N часов после последней публикации бота,
а если это время уже прошло — через N часов от текущего момента.

## Запуск

1. Создайте бота у [@BotFather](https://t.me/BotFather) и получите токен.
2. Скопируйте настройки и впишите токен:
   ```bash
   cp .env.example .env
   ```
3. Запустите.

   **Docker:**
   ```bash
   docker compose up -d --build
   ```

   **Без Docker** (Python 3.11+):
   ```bash
   python -m venv .venv && source .venv/bin/activate
   pip install -r requirements.txt
   python -m bot.main
   ```

4. Добавьте бота администратором канала с правом **«Публикация сообщений»**.
   Бот сам пришлёт сообщение, что канал подключён (если вы уже нажали /start).
   Если канал не появился — используйте `/add` и перешлите боту любой пост из канала.

## Команды

| Команда | Что делает |
|---------|-----------|
| `/channels` | выбрать канал |
| `/add` | добавить канал вручную (пересланный пост, `@username`, ссылка или id) |
| `/interval [часы]` | показать / изменить интервал и пересчитать очередь |
| `/queue` | очередь публикаций |
| `/cancel` | отменить текущее действие |
| `/help` | помощь |

## Настройки (`.env`)

| Переменная | По умолчанию | Описание |
|------------|--------------|----------|
| `BOT_TOKEN` | — | токен бота |
| `TIMEZONE` | `Europe/Moscow` | часовой пояс для отображения времени |
| `DEFAULT_INTERVAL_HOURS` | `1` | интервал для новых каналов |
| `DB_PATH` | `data/bot.db` | путь к базе SQLite |
| `ALLOWED_USERS` | пусто | id пользователей через запятую; пусто — без ограничений |

## Структура

```
bot/
  main.py        запуск, middleware доступа
  handlers.py    команды и приём постов
  service.py     операции с очередью (добавление, смена интервала, выравнивание)
  scheduling.py  чистая логика расчёта времени
  publisher.py   фоновая публикация наступивших постов
  db.py          SQLite (aiosqlite)
  config.py      настройки из .env
tests/           pytest
```

Тесты: `pip install pytest && python -m pytest`
